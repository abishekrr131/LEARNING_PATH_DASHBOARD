Project definitionWhat the system is, what it claims, and what it does not claim.An adaptive learning platform for two learner tracks — candidates preparing for Indian government examinations, and students preparing for IT careers. It assesses a learner, models their knowledge state over time from behaviour rather than from scores alone, locates the concept they are failing, infers which earlier concept probably caused that failure, remediates the earlier concept, and re-tests to confirm the gap closed.One-line definitionAn AI-driven adaptive learning system that models a learner's temporal response behaviour and concept dependency structure to detect learning gaps and their probable prerequisite causes, then personalizes resources, practice, scheduling and reassessment accordingly.The three things that distinguish it from a recommenderBEHAVIOUR, NOT SCORE   Response time and skips are featuresA wrong answer is ambiguous. Wrong-and-fast, wrong-and-slow, and skipped are three different learner states, and the model consumes all three.CAUSE, NOT SYMPTOM   Prerequisite attributionFailing Naive Bayes is frequently a conditional probability problem. The system walks the dependency graph to name the probable upstream cause.LOOP, NOT LIST   Remediate then re-testThe path is rewritten after every assessment, and the intervention's effect is measured rather than assumed.What the contribution is — stated carefullyGraph-based knowledge tracing already exists (GKT, SKT, GIKT). Prerequisite-aware tracing exists. Response-time-aware tracing exists. As an architecture claim, RCT-GAT is a recombination of known components, and a reviewer will say so. State the contribution as the combination plus one thing almost no knowledge-tracing paper does:POSITION THE PAPER HEREThe defensible contribution is the closed intervention loop measured on real learners: predict the root-cause prerequisite, remediate it rather than the surface concept, and show a larger downstream gain than the control arm. Knowledge-tracing papers almost never report this, because it needs a live platform with students — which this project has. Lead with the experiment; present RCT-GAT as the mechanism that makes it possible.Non-claims — put these in the paperRCT-GAT is not established as globally novel or patentable by this document.The system does not guarantee examination success or job placement. Readiness is an estimate.A fixed accuracy figure is not promised in advance. The reported number is whatever the held-out, leakage-free test produces. The learner journeySixteen stages, one closed loop. Every screen in §18 and every API group in §17 exists to serve one of these stages.Figure 1 The journey is a loop, not a funnel. The feedback edge is the whole product: every follow-up assessment re-enters inference with a longer history, so the path is recomputed rather than fixed at onboarding. Teal nodes are the two model-driven stages.Where each stage's data goesTrack and target selection decide the graph The chosen target scopes the competency subgraph and the item pool. Nothing downstream is global.The assessment engine logs behaviour, not answers Every item writes correctness, response time in milliseconds, skip flag, attempt number, item difficulty, concept id and a server-side timestamp.Inference runs on a sequence, not a snapshot The learner's full interaction history, ordered, is the model input. A first-time learner runs on a cold-start fallback — see §12.6.Suspicion is not a diagnosis A low predicted mastery triggers verification probes. Only a confirmed gap enters root-cause scoring, and probes are also served on unflagged concepts to keep the labels unbiased (§9.4).Remediation targets the ancestor The path engine inserts the top root-cause candidate upstream of the surface concept, then re-queues the surface concept behind it.The follow-up assessment is the measurement It is both a learner-facing re-test and the dependent variable of the intervention experiment in §13.3.4. RCT-GAT — the main algorithmWhat it is for, what each block does, and the two design corrections that decide whether it trains at all.PurposeRCT-GAT answers one supervised question — will this learner get the next item right? — and in answering it builds a representation from which three further quantities are read off: concept mastery, a ranked list of probable prerequisite causes, and the next concept to teach. It replaces three things a rule-based system would need: a hand-tuned threshold table, a hand-written prerequisite lookup, and a static curriculum order.Where it runsOffline for training (Celery / a GPU notebook). Online as a frozen checkpoint in the ml-inference service, called once per assessment submission and once per dashboard refresh (cached in Redis against the learner's interaction count, so an unchanged history is never re-inferred).Figure 4 RCT-GAT. Three encoders, one fused representation, three read-outs, one loss. The dashed band is the correction that matters most: the original specification implied three jointly trained objectives with labels for all three, two of which cannot be observed. The learned weights are the raw material for root-cause ranking, which is why this layer is not optional.Figure 5 One attention neighbourhood. Set operations is an ancestor but the learner holds it (M = 0.88) and the model attends to it weakly, so it is not a cause. Conditional probability combines the strongest learned attention with the weakest mastery, which is exactly the conjunction root-cause scoring looks for. Edge thickness is drawn proportional to α.6.4  Hyperparameters to reportEvery one of these belongs in the paper's experimental-setup section. Each states its purpose, defines every symbol, and carries a worked example with real numbers so the implementation can be checked against it.8.1  Model formulasF1 — Graph attention over the prerequisite neighbourhoode_ij = LeakyReLU( aᵀ [ W h_i ‖ W h_j ] )α_ij = exp(e_ij) / Σ_{k∈N(i)} exp(e_ik)h'_i = σ( Σ_{j∈N(i)} α_ij W h_j )Purpose: learn how much each neighbouring concept should contribute to a concept's representation, instead of trusting the hand-authored edge weight. Symbols: h_i concept embedding; W trainable projection; a attention vector; N(i) neighbourhood; ‖ concatenation; σ ELU.    Worked: with a = [0.4, 0.3, 0.6, 0.2], Wh_c = [1.0, 0.5], Wh_h₁ = [0.2, 0.9], Wh_h₂ = [0.9, 0.1] → e_c,h₁ = 0.85, e_c,h₂ = 1.11; softmax gives α₁ = 0.435, α₂ = 0.565. The contributions sum to 1 across the neighbourhood, which is what makes α readable as "share of explanation."F2 — Per-interaction input vectorx_t = [ emb(concept_t) ‖ correct_t ‖ log1p(timeratio_t) ‖ skip_t        ‖ b_t ‖ attempt_t ‖ log1p(Δt_t) ‖ priormastery_t ‖ prereqstate_t ]Purpose: the single row the temporal encoder consumes. Note: the label for position t is correct at t+1, never at t. Build the shift in one place and assert it in a test.F3 — Temporal encoding and fusionH = TransformerEncoder(x₁, …, x_t)       causal maskh_t = H[-1]z   = LayerNorm( [ h_t ‖ b_t ‖ g_c ] )     → 256-dPurpose: compress an entire learning history into one state vector, then join it with behaviour and graph context. Why the causal mask matters: without it position t can see position t+1, which is the label. That is not a subtle leak — it will produce an AUC above 0.95 and an unpublishable paper.F4 — Mastery read-outM_c = σ( W_m z_c + b_m )Purpose: a 0–1 estimate per learner×concept, used by the dashboard, the gap list and readiness. Scoring note: mastery is latent. Give it the operational definition in §12.3 before reporting any error metric against it.F5 — Next-performance prediction  [PRIMARY TASK] p̂ = σ( MLP( [ z ‖ emb(q_next) ‖ b_{q_next} ] ) )Purpose: the probability the learner answers the next item correctly. This is the only quantity with an unambiguous observed label, so it is the headline result. Second use: adaptive item selection — serve items where p̂ falls near 0.6–0.7, which is informative without being demoralising.F6 — Root-cause score  [REVISED] R(c,h) = σ( wᵀ [ z_c ‖ z_h ‖ α(c,h) ‖ (1 - M_h) ‖ E_h ] + b ) where  E_h = recent error rate on h, weighted by recencyPurpose: score each ancestor h as a probable cause of failure at c. The signal it looks for is a conjunction: the model attends to h strongly AND the learner does not hold h AND there is historical error evidence on h.    What changed: the hand-authored prerequisite strength P(h,c) has been removed from the feature vector. It still bounds the candidate set through ancestor enumeration, but it cannot be both an input and the source of the label. See §9.2.F7 — Training objectiveL = - (1/N) Σ_i [ y_i log p̂_i + (1 - y_i) log(1 - p̂_i) ]   + λ‖Θ‖²Purpose: one binary cross-entropy over observed next-item correctness, with L2 regularisation. Why only one: the mastery and root-cause outputs have no observable labels, so adding loss terms for them means inventing targets and then measuring agreement with your own invention. Derive them from z instead and validate them externally (§12.3, §13.3).F8 — Attention entropy, for honest attribution  [ADDED] H(c) = - Σ_{h∈A(c)} α(c,h) · ln α(c,h)H̄(c) = H(c) / ln |A(c)|          normalised to [0,1]Purpose: measure how concentrated the attribution is, and decide what the UI is allowed to claim.    Worked: for α = [0.61, 0.25, 0.14], H = 0.923 and ln 3 = 1.099, so H̄ = 0.84.    Design rule: when H̄ > 0.7 the model is not confident in a single cause — present the top two candidates as alternatives rather than asserting one. This costs nothing and keeps the product from overclaiming.8.2  Psychometrics and gap scoringF9 — Item Response Theory, two-parameter logisticP(X = 1 | θ) = 1 / ( 1 + exp( -a(θ - b) ) )Purpose: separate the item was hard from the learner is weak. Symbols: θ learner ability; b item difficulty on the same scale; a discrimination (how sharply the item separates learners).    Worked: a = 1.2, b = 0.8, θ = 0.3 → P = 1/(1 + e^{0.6}) = 0.354. A learner below the item's difficulty has a 35% chance, so getting it wrong is weak evidence of a gap — which is exactly why verification probes exist.F10 — Expected response time per difficulty bandExpectedTime(b) = median{ τ_i : item i in difficulty band of b, correct_i = 1 }Purpose: the denominator of the time ratio, estimated empirically rather than assumed. Why median and correct-only: the mean is dragged by abandoned tabs, and incorrect responses include guesses answered in two seconds. Recompute nightly; store per band, not per item, until each item has enough data.F11 — Response-time ratioTimeRatio = τ_student / ExpectedTime(b_question)Purpose: make response time comparable across items of different difficulty. This is the feature that lets the model distinguish struggling from guessing.    Worked: a hard item with ExpectedTime = 95s. Learner A takes 142s → ratio 1.49 (laboured but engaged). Learner B takes 38s → ratio 0.40 and answers wrong (almost certainly a guess). Same wrong answer, two different learner states, and only this feature separates them.F12 — Learning Gap ScoreG_c = w₁(1 - Accuracy_c) + w₂·TimePenalty_c + w₃·SkipRate_c + w₄(1 - M_c^hist) where  TimePenalty_c = clip( (TimeRatio_c - 1) / 2 , 0, 1 )       Σ w_k = 1Purpose: an interpretable severity score, used as the cold-start signal, the UI explanation, and the non-neural baseline.    Worked with w = (0.40, 0.20, 0.20, 0.20), accuracy 0.35, TimeRatio 1.49, skip rate 0.25, historical mastery 0.40:    G = 0.40(0.65) + 0.20(0.245) + 0.20(0.25) + 0.20(0.60) = 0.260 + 0.049 + 0.050 + 0.120 = 0.479 Bands: <0.30 strong · 0.30–0.60 moderate · >0.60 weak. So 0.479 is a moderate gap — worth a probe, not yet worth rewriting the path. The root-cause mechanismThe project's actual contribution, the circularity that would invalidate it, and how to evaluate it without inventing labels.9.1  Inference procedureSix steps, two of them guards. The guards are what separate an attribution from a guess.Figure 7 Root-cause inference. The two dashed and hollow branches are the guards: the ε-random probe keeps the training labels unbiased (§9.4), and the entropy check keeps the interface from asserting a single cause the model is not confident about (§8.8).9.2  The circularity, and the fixCORRECTION 4 — THE MOST SERIOUS ISSUE IN THE ORIGINAL SPECThe original R(c,h) takes the hand-authored prerequisite strength P(h,c) as an input feature, while the original labelling plan derives the root-cause label from "prerequisite structure." The model would therefore be trained to predict its own input, and any Top-K accuracy reported on it measures nothing. A reviewer will find this immediately.Three ways out. Take the first as primary and the second as a supporting result.Evaluate by intervention outcome, which needs no label at all Randomise confirmed-gap learners between remediating the predicted ancestor h* and remediating the surface concept c, then measure post-test improvement on c. If prerequisite-targeted remediation wins, the attribution was useful — which is the claim that matters. Design in §13.3, effect size in F23.Score against an external expert graph, with the feature removed Use a public corpus whose prerequisite graph was authored by subject experts (Junyi Academy ships one) as held-out ground truth, and drop P(h,c) from the feature vector so the graph appears only in the label, never in the input. Then Top-1 / Top-3 / MRR are meaningful.Sanity-check on synthetic learners Simulate learners from a known generative dependency structure, so the true cause is known by construction. This is a controlled correctness check for the mechanism, not evidence about real students — present it as such.9.3  What the path engine does with the resultFigure 8 Path transformation. A conventional recommender serves more Naive Bayes material. This system inserts the ancestor, teaches it, then re-queues the surface concept and re-tests it — and that re-test is the intervention experiment's dependent variable.9.4  The selection-bias trap in verification probesCORRECTION 5 — PROBE THE UNFLAGGED CONCEPTS TOOIf probes are served only where the model already predicted weakness, then every "confirmed gap" label exists only inside the model's own positive predictions. Train a gap classifier on those labels and its reported accuracy is inflated, while its false-negative rate is structurally unmeasurable — you have no labels where the model said "fine."Fix: serve a probe on a randomly chosen unflagged concept with probability ε ≈ 0.10. It costs each learner two or three extra items per session and it is the only way to obtain unbiased negatives. Record which branch produced each probe in verification_probes.trigger so the analysis can weight accordingly.10.  The generative AI layerGemini explains; RCT-GAT decides.
